# Quicio Foundry

Quicio Foundry is the **Quicio Engineering Foundation**: a project
generator that composes a base skeleton with a profile, a language,
and a selected set of features to produce a working, verifiable
project.

It is **not** a runtime library. It is **not** a domain library. It
does not share entities with Speck or OpenSpec.

## Status

**Pre-implementation.** This repository currently holds only the
OpenSpec change proposal under `openspec/changes/quicio-engineering-foundation/`.
**No code is to be written until the proposal, design, specs, and
tasks are reviewed and approved.**

## Composition model

```
base + profile + language + selected features
```

Initial axes (v0):

- **Profiles:** `library`, `application`, `experiment`
- **Languages:** `typescript`, `python`
- **Features:** named placeholders only
  (`openspec-bootstrap`, `speck-integration`,
  `github-actions`, `docker`). Real implementations land in
  follow-up OpenSpec changes once a concrete consumer exists.

## Verification contract (every generated project)

Every project generated by Foundry MUST expose working
`check`, `test`, `build`, and `format` commands. A generated
project that lacks any of these is a bug in the generator, not a
project decision.

## Specs

The full specification lives in
`openspec/changes/quicio-engineering-foundation/`:

- `proposal.md` — the why, the goals, the non-goals, success criteria.
- `design.md` — module boundaries, composition model, dependency
  direction, failure modes.
- `tasks.md` — TDD-shaped vertical slices grouped by capability.
- `specs/<capability>/spec.md` — one spec per capability with
  testable `SHALL` requirements and `WHEN/THEN` scenarios.

Run `openspec validate --changes` to check that the change is
well-formed.

## CLI (planned for v0, not yet implemented)

```
quicio new <project> [options]

  -p, --profile <name>     library | application | experiment (default: library)
  -l, --language <name>    typescript | python (default: typescript)
      --with <feature>     repeatable, opt-in
      --without <feature>  repeatable, opt-out
      --out <dir>          target directory (default: cwd)
      --force              allow non-empty target
      --dry-run            print plan, write nothing
      --no-verify          skip post-generation smoke test
```
